nbplay.widget¶

The nbplay widgets: instruments on transports models, rendered by spaday.

A widget hosts a config model (kernel-owned, validated) and a status model (browser-owned) in a transports.Session, and renders the instrument element with spaday bindings: config fields bind two-way on nbplay-set, status fields two-way on nbplay-status, and an nbplay-wire child delivers session.command calls to the element.

bind_slot_editor(sequencer)[source]¶

Edit whichever slot is selected in sequencer (a SequencerWidget); returns an unbinder.

Selecting a slot, in the browser or by assigning config.selected_slot, loads it into the sequencer; the sequencer’s step, grid, swing and groove edits write back into that slot. A slot replaced while it is selected (set_slot(), undo) is loaded again.

Each load gives the sequencer an edit_token, and the browser precedes every pattern edit with an edit_ack naming the token it was made on. An edit made before the browser saw the current slot is dropped instead of landing on it.

class nbplay.widget.Session(bpm=120.0, time_signature=(4, 4), theme='')[source]¶

Transport, mixer, timeline and launcher widgets sharing one browser session.

Every widget carries the same session_id, so the browser gives them one audio bus and one clock, which keeps play state, position and tempo consistent across them. Each widget hosts its models in its own transports Session: transports grants a connection ownership of every client-owned field in the session it connects to, so widgets that shared one would fight over each other’s status. In the kernel the bpm, time_signature and theme properties write every widget’s config, history records every widget’s config edits for undo() and redo(), and lane mute and solo mirror the mixer channels. add_pattern() and chain() lay named patterns out as clips, and export_midi() and import_midi() move the arrangement through .mid files, and save() and load() read and write the same .nbplay archive as the traitlets nbplay.widget.Session.
