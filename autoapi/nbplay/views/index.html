nbplay.views¶

Views: nbplay instruments on transports models, rendered by spaday.

A view hosts a config model (kernel-owned, validated) and a status model (browser-owned) in a transports.Session, and renders the instrument element with spaday bindings: config fields bind two-way on nbplay-set, status fields two-way on nbplay-status, and an nbplay-wire child delivers session.command calls to the element. This is the parallel layer to the traitlets widgets in nbplay.widget; it needs spaday[widget] with notebook session support and transports 0.12.

class nbplay.views.Session(bpm=120.0, time_signature=(4, 4), theme='')¶

Transport, mixer, timeline and launcher views sharing one browser session.

Every view carries the same session_id, so the browser gives them one audio bus and one clock, which keeps play state, position and tempo consistent across them. Each view hosts its models in its own transports Session: transports grants a connection ownership of every client-owned field in the session it connects to, so views that shared one would fight over each other’s status. In the kernel the bpm, time_signature and theme properties write every view’s config. Undo, patterns, MIDI files and persistence stay with the traitlets nbplay.widget.Session for now.
